# Datasets, labels, windows, and embeddings

TRACE uses licensed or separately distributed video benchmarks. This package contains loaders and split protocols, not videos or annotations. Obtain each dataset from its official distributor and follow its current access and redistribution terms. Do not rename source videos or annotations; the loaders depend on their original identifiers.

Set the data and embedding locations before running commands:

```bash
export TRACE_DATASET_ROOT=/absolute/path/to/datasets
export TRACE_EMBEDDING_ROOT=/absolute/path/to/embeddings
```

By default, the code looks under `data/datasets/` and `data/embeddings/` in this repository.

## Benchmark descriptions and paper protocols

| Dataset | Description and target surface | Protocol used in the paper | Expected annotations |
|---|---|---|---|
| BARISTA | Fine-grained beverage-preparation activities. Activity targets are action labels; otherwise unlabeled windows receive the `SIL` label. | Deterministic sequence-level hash split `s1` (129/28/28 train/val/test sequences); main comparison and interventions. The official train/test field of the release is available as `--test-split official`. | `Barista/Image_data/`, `Barista/labels/` and `Barista/splits/`, generated from the official release by `utils/prepare_barista.py` (see below). |
| Breakfast Actions | Long cooking and food-preparation videos annotated with temporal action segments. | Official s1–s4 splits; results are averaged within seed for the main comparison. Ablations and intervention studies use s1. | `Breakfast/breakfast_segmentation_coarse/` and `Breakfast/Video_data/`. |
| MPII Cooking 2 | Cooking and daily-manipulation videos with two label protocols in this release. | `Attr` is used in the main comparison and intervention studies; `Dishes` is supplementary. | `MPII_Cooking_2/annotations/`, including `attributesAnnotations_MPII-Cooking-2.mat` and the official `experimentalSetup` split files. |
| GTEA Gaze | Egocentric cooking videos with verb-label targets in this evaluation. Unlabeled intervals are mapped to `SIL`; interpret results with the high unlabeled-window rate. | s1 verb targets; supplementary calibration diagnostic, not part of the main aggregate. | `GTEA_Gaze/action_annotation/raw_annotations/` and official video files. |
| EPIC-KITCHENS-100 | Egocentric kitchen videos; targets are composite verb–noun action labels. Unlabeled intervals are mapped to `SIL`; report calibration alongside accuracy. | s1 action targets; supplementary calibration diagnostic, not part of the main aggregate. | `EPIC-KITCHENS-100/annotations/epic-kitchens-100-annotations/` and official video files. |
| Synthetic delayed dependency | Controlled sequence task with six planted delayed concept relations; it does not use real video or dataset downloads. | Seeds 42–44; supplementary mechanism diagnostic. Predictive performance does not establish causal recovery. | Generated by the synthetic task code; no external annotation tree. |

Breakfast, MPII Cooking 2, GTEA Gaze and EPIC-KITCHENS-100 use their official released splits and media. BARISTA uses the official media and annotations with the sequence-level hash split described in the BARISTA section below. Dataset-specific loader behavior is implemented in `utils/dataset_handling.py` and `utils/prepare_datasets.py`. The synthetic task is generated by the existing training code. The paper’s dataset and label protocol is described in the evaluation appendix; the release preserves those label choices, including the distinct GTEA verb and EPIC composite-action targets.

## BARISTA preparation

The official BARISTA release ([ramblr/BARISTA](https://huggingface.co/datasets/ramblr/BARISTA)) stores one directory per video with `coco_annotation.json` and `video.mp4`. The TRACE loader does not read this layout directly; convert it once with the bundled script:

```bash
huggingface-cli download ramblr/BARISTA --repo-type dataset --local-dir /path/to/BARISTA
python utils/prepare_barista.py prepare --source-root /path/to/BARISTA   # writes $TRACE_DATASET_ROOT/Barista
python utils/prepare_barista.py validate                                  # also run by batch_scripts/check_data.py
```

The conversion reproduces the preparation used for the paper:

- **Frames.** Every source frame is extracted with ffmpeg at the native frame rate (about 30 FPS) and native resolution (720p–1080p), named `frame_{source_frame_index + 1:06d}.jpg`. There is no temporal resampling; a 32-frame window therefore covers roughly 1.07 s. `--max-side` can downscale frames to save disk space (the paper used full resolution); the frame indices are unchanged.
- **Sequence ids.** `<document_id>__video_<video_index>`, i.e. `<document_id>__video_0` for every released video. `Image_data/<sequence_id>/source_info.json` records the source FPS, frame count, resolution and the official split of each video.
- **Labels.** `activity_labels.csv` has one row per source frame. The primary `activity_label_index` of a frame covered by overlapping activity segments is the segment that starts last (ties: longer segment, then later annotation order); all overlapping labels are kept in the pipe-separated `activity_label_indices` column. Frames outside every activity have index `-1` and yield `SIL` windows under the default `--activity-label-fill-mode sil`. `activity_segments.csv` copies the official `image_range` as inclusive 0-based `start_frame`/`end_frame`. Class indices are assigned alphabetically by display name (`activity_classes.csv`).
- **Window alignment.** Window labels are computed from the frame rows using the embedding window size: window *k* covers source frames `[32k, 32k + 31]` and the final partial window covers the remaining frames, matching the embedding pipeline. The label of a window is the majority non-background frame label; windows without any labeled frame are `SIL`.
- **Splits.** The paper results use `--test-split s1`, a deterministic sequence-level split (sequence ids sorted by SHA-1 hash, ~70/15/15 train/val/test, i.e. 129/28/28 sequences). It is written to `splits/s1_hash.json` for reference and does **not** coincide with the official train/test field of the release. `splits/official.json` keeps the official test set (37 videos) and carves `--val-fraction` (default 0.15) of the 148 official training sequences out as validation (126/22/37); select it with `--test-split official`. Any JSON file with `train`/`val`/`test` sequence-id lists can also be passed as `--test-split /path/to/split.json`. Both mappings and the official per-video split field are checked in under `configs/splits/` (`barista_s1_hash.json`, `barista_official.json`, `barista_official_split_field.json`); `--test-split official` falls back to the checked-in copy when the dataset folder has no `splits/`, and `python utils/prepare_barista.py splits --official-split-field configs/splits/barista_official_split_field.json` regenerates the folder's split files without re-downloading the release. The two test sets differ substantially: only 7 of the 37 official test videos are in the `s1` test set.

## Windowing and frame sampling

The embedding pipeline partitions each video into consecutive, non-overlapping 32-frame windows and retains a final non-empty partial window. It samples eight frames uniformly within each window; a short partial window repeats its last frame as needed. The saved embedding artifact contains `video_window_spans`, which records the time interval of each full source window. For image-folder datasets the timestamps use the FPS recorded in `source_info.json` (BARISTA) and fall back to 12 FPS otherwise; BARISTA window labels are aligned by frame index and do not depend on these timestamps. Training draws windows using the configured uniform training sampler; the model observes five windows and forecasts horizons H1–H3.

## Embedding commands

The reported benchmark protocols use frozen PE-L14 video features and 128-concept vocabularies. Generate main-dataset embeddings with the Slurm array:

```bash
sbatch batch_scripts/01_embed_main.sbatch
```

Generate the supplementary real-video embeddings with:

```bash
sbatch batch_scripts/07_embed_additional.sbatch
```

Equivalent single-dataset command:

```bash
python embed_dataset_backbones.py \
  --dataset barista \
  --models pe-l14 \
  --window-size 32 \
  --num-gpus 1 \
  --pe-video-batch-size 1 \
  --pe-target-t 8 \
  --seed 42
```

Expected PE-L14 outputs:

```text
$TRACE_EMBEDDING_ROOT/Barista/True_32_clip_pe-l14_state.pkl
$TRACE_EMBEDDING_ROOT/Breakfast/True_32_clip_pe-l14.pkl
$TRACE_EMBEDDING_ROOT/MPII_Cooking_2/True_32_clip_pe-l14_state.pkl
$TRACE_EMBEDDING_ROOT/GTEA_Gaze/True_32_clip_pe-l14_state.pkl
$TRACE_EMBEDDING_ROOT/EPIC-KITCHENS-100/True_32_clip_pe-l14_state.pkl
```

Check inputs with `python batch_scripts/check_data.py` for the main datasets or add `--include-additional` for GTEA and EPIC-KITCHENS-100. Embedding files and caches are generated locally and are not part of this repository.

## Frozen concept vocabularies and regeneration

The 128-concept vocabularies used by the model are included in `concepts/`. Vocabularies are dataset-specific and are not the activity labels. Their training split is used for offline proposal, retrieval, verification, deduplication, and label-overlap filtering. Qwen’s initial storyboard observations are label blind; activity-label information is used only for balanced sampling and leakage filtering. The VLM does not see future test labels.

To regenerate the three vocabularies supported by the checked-in Qwen3.5-27B config (BARISTA, Breakfast, MPII Cooking 2), first create PE-L14 embeddings and run a local compatible vLLM endpoint. Then run:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3.5-27B \
  --revision fc05daec18b0a78c049392ed2e771dde82bdf654 \
  --host 127.0.0.1 \
  --port 8000 \
  --dtype bfloat16 \
  --max-model-len 32768
```

In another shell from the repository root, run:

```bash
python utils/generate_concept_sets.py \
  --config utils/concept_generation_qwen35.json \
  --vlm-endpoint http://127.0.0.1:8000
```

Concept generation needs the included small bootstrap vocabulary JSON files and a training embedding artifact for each selected dataset. It creates text-embedding caches and run metadata locally. Regenerated vocabularies are a new experimental condition; retain the included frozen files to reproduce the reported runs.
